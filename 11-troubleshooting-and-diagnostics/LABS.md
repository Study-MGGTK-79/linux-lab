# Лабораторная работа 11: Безопасность ядра, аудит контейнеров и обнаружение скрытых угроз

## 🎯 Цели работы
1. Освоить методы аудита изоляции контейнеров и выявления рисков побега на хост (Container Escape).
2. Научиться обнаруживать признаки скрытых процессов и манипуляций ядром с помощью детекторов рассогласования.
3. Реализовать комплексный харденинг ядра Linux через `sysctl` для защиты KASLR и предотвращения атак на память.
4. Исследовать системные вызовы с помощью `strace` для поиска скрытых сетевых соединений и файловых дескрипторов.

---

## 📁 Стартовые данные
В каталоге `11-troubleshooting-and-diagnostics/starter_data/`:
- `hidden_proc_detector.py` — утилита поиска рассогласований между планировщиком ядра и `/proc`.
- Скрипты симуляции утечки дескрипторов и аномалий процессов.

## 📝 Задания

### Задание 1: Аудит привилегий контейнера и рисков побега
1. Выполните команду проверки текущих возможностей процесса:
   ```bash
   capsh --print
   ```
2. Проанализируйте список `Current`:
   - Присутствуют ли опасные привилегии: `cap_sys_admin`, `cap_sys_ptrace`, `cap_sys_module`, `cap_net_admin`?
   - К каким рискам приводит наличие `cap_sys_admin` внутри контейнера?
3. Проверьте видимость блочных устройств:
   ```bash
   ls -la /dev/sd* /dev/nvme* /dev/loop* 2>/dev/null
   ```
   Если непривилегированному контейнеру доступны устройства сырых дисков хоста — опишите вектор монтирования корневой ФС хоста.

---

### Задание 2: Обнаружение скрытых процессов ядра
1. Запустите разработанный детектор:
   ```bash
   python3 starter_data/hidden_proc_detector.py
   ```
2. Разберите принцип работы: почему отправка сигнала `0` функции `kill()` позволяет обнаружить процесс, даже если руткит скрыл директорию `/proc/<PID>`?
3. Сформулируйте алгоритм действий дежурного SRE/SOC-инженера при обнаружении PID в выводе детектора.

---

### Задание 3: Комплексный харденинг параметров ядра (`sysctl`)
Создайте конфигурационный файл `/etc/sysctl.d/99-security-hardening.conf` со следующими директивами:
- Скрытие указателей ядра (`kptr_restrict = 2`).
- Ограничение доступа к dmesg (`dmesg_restrict = 1`).
- Отключение непривилегированного eBPF (`unprivileged_bpf_disabled = 2`).
- Защита ptrace через Yama (`ptrace_scope = 2`).
- Защита от SYN-флуда (`tcp_syncookies = 1`).
- Запрет перенаправления пакетов (если хост не является маршрутизатором): `ip_forward = 0`.

Примените изменения командой `sudo sysctl -p /etc/sysctl.d/99-security-hardening.conf` и убедитесь в их активности.

### Задание 4: Трассировка подозрительной активности через `strace`
1. Запустите трассировку сетевых системных вызовов команды curl:
   ```bash
   strace -e trace=network,openat curl -s https://example.com > /dev/null
   ```
2. Изучите последовательность вызовов `socket()`, `connect()`, `sendto()`, `recvfrom()`.
3. Как с помощью `strace -p <PID> -f` отслеживать сетевую активность демона, скрывающего свои порты от `ss`?
